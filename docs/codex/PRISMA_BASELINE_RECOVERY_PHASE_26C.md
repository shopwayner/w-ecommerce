## OrderItem decisions

### `updatedAt`

Production has `DEFAULT CURRENT_TIMESTAMP`; the previous Prisma model used only
`@updatedAt`. Current application code has no active OrderItem persistence path:
the orders POST endpoint only validates and returns a prepared response, while
the seed deletes OrderItems before Products. Retaining the database default is
the conservative behavior for raw/import writers and matches the audited
physical schema. Prisma now declares `@default(now()) @updatedAt`.

No corrective DDL is required for this field because the default is already in
the baseline. A Prisma Client fixture proved creation receives a timestamp and
an update advances it.

### `productId`

Production used `ON DELETE RESTRICT`; the intended Prisma relation is optional.
`ON DELETE SET NULL` preserves the immutable order-item snapshot (`sku`, `name`,
prices, quantity, and raw JSON) while removing only the link to a deleted
Product. The correction does not cascade or delete historical orders.

`20260823000100_align_order_item_schema` drops and recreates only this FK with
`ON DELETE SET NULL ON UPDATE CASCADE`. SHA-256:

`6aca24c2005c2ba1f17f0610e4548f1673a7f34882430fe98b869935a8da3485`

Disposable fixtures proved Product deletion nulls `OrderItem.productId`, keeps
the Order and OrderItem, and Order deletion still cascades to its items.

## Validation results

On a completely empty PostgreSQL 17 database:

- `prisma migrate deploy`: success;
- `prisma migrate status`: up to date;
- `prisma validate`: success;
- `prisma generate`: success;
- migration rows: 2 finished, 0 unfinished, 0 rolled back;
- structural diff against the candidate schema: empty.

On a schema-only production clone with the 32 historical administrative rows:

- initial status: divergent;
- resolving only the baseline: still divergent because 31 finished legacy
  migrations were absent from the candidate filesystem;
- after disposable administrative history replacement, the corrective migration
  executed normally;
- final status: healthy;
- final structural diff: empty.

This proves that a future production reconciliation needs both a resolved
baseline and an explicitly authorized replacement of the legacy administrative
history. No such operation was performed in production.
